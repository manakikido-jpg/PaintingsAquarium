# 設計: 必ず映る（取り込みで1枚も落とさない）

- 2026-10-16 作成 / 状態: **設計のみ。実装前**
- きっかけ: 本人「映る映らない の問題は確実に消せる方法はない？」
- 関連: R-067 / R-068（影ムラ）/ R-069 / 要件定義 §3

---

## 1. いま何が起きているか

絵が画面に出ないことがある。原因は**取り込みの拒否**。

`src/renderer/processImage.ts` の最後。

```ts
if (!attempt) return { ok: false, message: `${fileName}: ${refusalMessage}` }
```

いまの切り抜きは、**紙のどこが絵なのかを写真から推測**している。
明るさのしきい値を選び（R-020）、紙を消し、残った塊を絵として採る。
影ムラのときだけ区画ごとに測り直す（R-068）。
それでも決まらなければ `nothing-left` / `nothing-removed` で**拒否**する。

推測なので外れる。実際に落ちた記録:

| いつ | 何枚 | 何が起きたか |
|---|---|---|
| 9/5 のイベント | 6枚 | 11分間だけ照明が崩れ、紙の白の彩度が 0.056 → 0.18〜0.19 になった |

**拒否されると、その子の絵は画面に出ない。**
スタッフには知らせが出るが、塗った本人から見れば「出なかった」だけ。
この企画は「自分の絵が大画面で動く」ことが全部なので、ここが一番重い失敗になる。

---

## 2. 確実に消せる理由

**台紙を自分たちで刷っているから。**

`tools/make-sheets.py` の置き方は完全に決まっている。

| | |
|---|---|
| 紙 | A4 よこ・300dpi（`A4_LANDSCAPE` / `DPI`） |
| 余白 | 14mm（`MARGIN`） |
| 上から | 題 → 副題 → 9mm 空ける（`TITLE_GAP`）→ 絵 |
| 絵 | 残った枠の中央。枠に対して 0.7倍（`ART_SCALE`） |

つまり**絵がページのどこにあるかは、写真を一切見なくても分かる**。
明るさも影も紙の色も関係ない。計算だけで出る。

ここから、**推測が全部失敗したときの最後の手段**が作れる。

> **決まった枠で機械的に切り出して、必ず出す。**

---

## 3. 決めること

### 3-1. 枠をどう知るか

**`make-sheets.py` に出させる。** アプリ側で同じ計算を書き直さない。

理由: `top_of_art` は**題の文字の高さを実測して**決まり、絵の位置は
その絵の縦横比で変わる。同じ計算を2か所に書くと、片方だけ直したときに
黙ってずれる（R-075 と同じ型）。

`make-sheets.py` が16枚すべてを並べて、次の2つを出す。

1. **全部の絵を含む一番小さい矩形**（ページに対する割合）
2. **どの題にもかからない上端**（一番背の高い題の下）

この2つから**1つの安全な枠**を決め、生成した定数としてアプリに渡す。

```
src/core/sheetBox.ts   ← make-sheets.py が書く。手で編集しない
```

**単体テストで固定する**（`make-sheets.py` が出した16枚ぶんの実測値を使う）。

- 枠は **16枚すべての絵を欠けずに含む**
- 枠は **16枚すべての題を含まない**

ここが崩れたら、台紙を足したときに気づける。

### 3-2. いつ発動するか

**推測が全部失敗したときだけ。** 通る写真は1画素も変わらない。

```
trySealRatios が全部失敗
  → 影ムラの再挑戦（R-068）も失敗
    → ここで初めて「枠で切る」
```

### 3-3. 発動してよい写真の条件

**何でも受け取ってはいけない。** 関係のない書類をスキャンしても出てしまう。
次を全部満たすときだけ。

| 条件 | 理由 |
|---|---|
| 縦横比が A4 の ±8% 以内 | 台紙でない紙を弾く |
| 長辺 1500px 以上 | 小さすぎる写真では枠の精度が出ない |
| よこ向き（幅 > 高さ） | 台紙はよこ向き。たて置きのスキャンは弾く |

**斜めに置かれた紙は救えない。** 枠は紙がまっすぐである前提なので、
傾いていると絵の端が欠ける。ここは正直に「救えない」とする。

### 3-4. 切り出したあと何をするか

枠で切ったあとも、**その中でもう一度だけ紙を抜く**。
枠の中はほぼ絵なので、通常よりずっと緩いしきい値でよい。
抜けなければ**紙ごと（白い四角のまま）出す**。

**種類の判定は、やってみて付かなければ付けないまま出す。**
フランケンが歩かず漂う、ということは起こる。**それでも出す。**

### 3-5. スタッフにどう見せるか

**操作は増やさない**（この企画の核心は「スタッフのアプリ操作0回」）。
左下のお知らせに1行出すだけにする。

> `05_franken.jpg: うまく切り抜けなかったので、台紙の枠で切って出しました`

**「失敗したこと」を隠さない。** 会期のあとで紙を見直せるようにする。

### 3-6. 切り替え

設定画面に `必ず映す`（既定 **入**）を足す。
`Settings` に `alwaysShow: boolean` を増やす。

**既定を「入」にする理由**: 落ちた6枚のような事故のほうが、
白い四角が1枚出ることよりずっと重い。
ただし**切れる**ようにしておく（会場で見た目が気になったとき用）。

## 4. これで何が保証されるか／されないか

| | |
|---|---|
| ✅ **自分たちが刷った台紙**を、ふつうの向き・大きさで取り込んだら**必ず出る** | |
| ⚠️ きれいに出るとは限らない | 紙の白が薄い四角として残ることがある |
| ⚠️ 種類が付くとは限らない | 付かなければ漂う（歩かない） |
| ❌ 斜めに置いた紙 | 絵の端が欠ける |
| ❌ スマホで撮った写真 | 絵の位置が決まらない |
| ❌ 白紙に自由に描いた絵 | 同上 |

**「必ず映る」は作れるが、「必ずきれいに映る」は作れない。**
ここを混ぜて説明しない。

## 5. 検証

1. **落ちた紙で試す。** 9/5 に拒否された6枚が手元にあるなら、それを通す。
   無ければ、`make-sample-scans.py` の紙に強い色かぶりと影をかけて作る
   （**合成は本物の代わりにならない**ので、これは最低限）
2. **通っていた紙が1枚も変わらないこと。** 実データ400枚を通し直して、
   切り抜き結果が**完全に同一**であることを確かめる（発動条件に入らないため）
3. 枠の単体テスト（§3-1）
4. 実機で、枠で切った絵が実際に泳ぐところまで見る

---

## 6. やらないこと

- **一覧から「もう一度画面に出す」** — 本人判断で**要らない**（2026-10-16）。
  スタッフの操作を増やさない。
  なお「一度出た絵が同時表示数を超えて去る」のはこの設計では解決しない。
  別の問題なので、困ったときに別途考える。
