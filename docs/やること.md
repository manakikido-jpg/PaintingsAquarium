## 水族館を直す（2026-08-24 に測った・着手前）

**恐竜テーマを作っている間に、水族館側が置いていかれている。**
下は実測した順に並べてある。数字はすべて 1920×1080・この開発環境（**GPUなし**）。
**会場のWindows機ではもっと出るはずなので、ここの数字は下限として見ること。**

### 1. 速さ（いちばん大きい）★

絵24枚で **19fps**。50枚だと **16fps**。層ごとに外して測った結果:

| 外したもの | fps | そのぶんの重さ |
|---|---|---|
| （そのまま） | 19 | — |
| **揺らぎ模様 2枚** | **42** | **約29ms** ← 断然これ |
| 　うち細かいほう1枚だけ | 26 | 約14ms |
| 動かない層（水・砂・パーツ・暗がり） | 25 | 約13ms |
| 光の筋 | 21 | 約5ms |
| 泡 | 20 | 約1ms |
| 背景を全部止める（強さ0） | 60 | — |

やること（効く順）:

1. **揺らぎ模様を軽くする。** いまは 640/520 の面に計算して引き伸ばしている
   （`drawCaustics.ts`）。**毎フレーム作り直す必要は無い**ので、
   (a) 計算する面をもっと小さく (b) 2〜3フレームに1回だけ更新
   (c) 数コマぶん焼いておいて順番に出す、のどれか。**19 → 40 前後を狙える**
2. **動かない層を1枚に焼く。** 水・砂・パーツ・周辺の暗がりは**動かない**のに
   毎フレーム描いている。`bake.ts` の仕組みが既にあるので、まとめて1枚にして
   `drawImage` 1回にする。**+6fps ほど**
3. 光の筋と泡は後回し（合わせて6ms）

> **注意**: この環境はソフトウェア描画。会場PCで先に測ってから決めてもよい（T-3）。
> ただし 1 は実機でも効くので、先にやって損はない。

### 2. ウミガメが画面の下に溜まる

90秒の実測で、**ウミガメは滞在時間の 49% が画面の一番下（5等分の最下段）**。
上段は 0%。下段は背景の岩とサンゴがある帯なので、**絵が飾りに埋もれて探せない**
（要件定義 §3 5c に反する）。ほかの種類は上下に散っている
（魚 31/14/18/23/15、クラゲは上寄り、イルカは跳ねるので上下）。

やること: ウミガメの上下の動きを見る（`behaviour.ts` の `wave` と、`spawnFish` の
初期の高さ）。**下に張り付く理由を先に測ってから**直すこと。

### 3. 台紙の見分けが際どい（水族館は恐竜より重い）

`python3 tools/check-templates.py assets/templates` の結果:

| 組 | 重なり |
|---|---|
| まる魚 ↔ タコ | 0.66 |
| タコ ↔ ウミガメ | 0.57 |
| まる魚 ↔ ウミガメ | 0.57 |
| まる魚 ↔ クラゲ | 0.55（**見分けの差 +0.00**） |

見分けの試験自体は 48/48 で通っているが、クラゲとまる魚の差が **+0.00**。
**恐竜と違い、水族館は種類ごとに泳ぎ方が違う**ので、外すと動きが変わる
（クラゲが魚として判定されると、漂わずに直進する）。

やること: **クラゲの台紙を縦長（比 2:1）に作り直す**。
形が離れて、印刷用の解像度不足（T-1）も同時に解消できる。

### T-1 に必要なもの

1. ~~台紙の線画~~ → **6種そろっている**（`assets/templates/`）。
   輪郭は全部閉じていて、見分けの試験も 48/48 で通っている。
   ただし**印刷には解像度が足りない**（376〜500px。A4でギザギザになる）ので、
   長辺2000px以上で作り直しが要る。クラゲは縦長に作り直すと更に安全になる
2. **実際に塗った紙を撮った写真を、1種類につき2〜3枚**

2 があれば、照合のしきい値を実測で決められる。
いまの暫定値（0.7）は自由に描いた絵3枚で測ったもので、
**本番（輪郭が台紙と同一）では当てはまらない可能性が高い**。

台紙を作るときの制約: **まわすと重なる形を2種類入れない**
（縦長と横長など）。形だけを見ているので原理的に区別できない。
