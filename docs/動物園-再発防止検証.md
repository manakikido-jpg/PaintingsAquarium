# 動物園の保存・表示の再発防止検証

2026-11-12。レビュー用ブランチ `feat/drawing-zoo` の検査記録。会場版への公開・自動更新は行っていない。

## 再現して直した問題

| 条件 | 修正前の実アプリ | 修正後 |
|---|---|---|
| 種類不明の動物園画像に旧魚用リグが残る | 魚の帯分割による波打ちを検出 | 展示テーマを優先し、魚用変形0回 |
| ゾウ・キリンのテーマ記録だけ欠ける | 水族館へ入り、長辺約90px（1280×800） | 動物園へ入り、同条件で約192px／248px |
| 連続受付後、処理待ち中に水族館ボタンを押す | 12枚中11枚が水族館として保存 | 12枚すべて受付時の動物園として保存 |
| 90度回った旧PNGを自動更新、画像読込を2秒遅延 | 旧画像を新寸法へ描く不一致296回 | 6枚の更新中、不一致0回 |

種類が別テーマ・不正値の場合も、展示テーマに適した標準表示へ戻す。テーマも種類もない古い自由画は従来どおり水族館に残す。1件の取り込みエラーで後続の画像を止めず、再投入方法を通知する。サイズ設定の非数値は標準倍率1へ戻す。

## 検証の内訳

- 単体テスト **584件／36ファイル**、typecheck、build成功。
- 実Electronの画像処理・保存・画像再読込・作り直しを **75ケース**で確認。6種×12条件（白黒A4、色付きA4、切抜画像、90/180/270度回転、±6度傾きJPEG、薄い色、グレーJPEG、余白の線、動物につながる大きな線）と、白紙・灰色紙・壊れた画像3件。
- 72枚保存。70枚が正しい種類、2枚が未判定、別種類への誤判定0枚。無効な3件は保存されない。
- 大きな接続線を除いた66ケースは、種類だけでなく保存画像の縦横比も台紙の外接矩形と比較し、規定内（対数比差0.10、±6度は0.25）。作り直しでも縦横比を維持。
- 種類不明6枚・テーマ欠損2枚・異テーマの種類2枚を表示。1280×800、800×600、1920×1080、3840×2160、2560×720の5解像度で標準サイズ・地面位置・魚用分割0回を確認。
- 実フォルダ監視で壊れた1枚に続けて12枚を取り込み、テーマ切替後も12枚すべて正しい種類・受付テーマで保存。
- 旧PNG6枚を再判定・向き補正して更新。透明部分は画素単位で一致、可視部分のRGB平均誤差は8未満（WebP圧縮を含む）。Canvasへ渡る画像URLも新しい版へ切り替わる。
- プロセスを終了し同じ隔離プロファイルで再起動。72枚すべてのテーマ・種類・幅・高さが保存結果と一致。非数値サイズ設定も標準倍率1で読込。

## 再実行の入口

実データのない隔離プロファイルだけで実行する。Python側はPillow・NumPy・Playwright、Node側はリポジトリの開発依存を使用する。

- `tools/audit-zoo-imports.py`: 75入力を生成し、実処理・保存・作り直しを検査。監視先が `<出力先>/inbox` と一致しない場合、既存の実データがある場合は中断する。`--check-results` で結果の縦横比を再検査できる。
- `tools/audit-zoo-display.py`: 専用の旧保存データでCanvasの分割描画・表示寸法・地面位置を5解像度で検査。
- `tools/audit-zoo-queue.py`: 専用監視フォルダへの投入と実際のテーマボタン操作を検査。
- `tools/audit-zoo-rebuild.py`: 専用シードを使い、旧PNG更新中の描画縦横比と保存後の色・透明部分を検査。

各スクリプトの `--help` に引数を記載。表示・待ち行列・更新の検査は、この監査で用意した専用シード構成が前提で、会場データへ直接実行しない。

## 残る確認範囲

検査画像は台紙から作った合成データであり、会場の原本スキャン・実スキャナ・Windows実機では未確認。Windows CIのパッケージ作成成功は、会場PCでの動作確認の代わりにはならない。

大きな線が体につながるキリンとしまうまは種類不明になった。魚用変形や7%への縮小は起きないが、線を含めた切抜範囲に合わせるため、動物本体が相対的に小さく見える場合は残る。今回のキリンでは元の表示の約68%。どんなはみ出しでも本体サイズや向きを保証できるものではない。しっぽの切分けが合わない実スキャンは、既存のしっぽ設定をオフにして歩行を維持できる。
