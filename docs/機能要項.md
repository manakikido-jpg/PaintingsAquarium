実装・追加した機能を継続的にまとめる台帳。
**機能を追加・変更したら必ず本ファイルを更新すること。**

- 最終更新: 2026-08-12

凡例: ✅ 実装済 / 🟡 雛形（枠のみ） / ⬜ 未着手

## 機能ID の付け方

カテゴリごとに百番台を割り当て、通し番号にする。
**一度振った番号は変えない。** 番号でドキュメント間を参照するため。

| 番号帯 | カテゴリ |
|---|---|
| 100 | 基盤・共通（起動・設定・保存） |
| 200 | 取り込み（監視・透過・トリミング） |
| 300 | 水槽（描画・アニメーション・全画面） |
| 400 | 運営（一覧・削除・集計） |
| 500 | テーマ（世界の差し替え） |

- 2026-08-18 F-209, F-210, F-324: **タコとイカを魚と違う動きにし、しきい値を自動で選ぶようにした**。
  実物のタコ・イカをもらって通したところ、**うまくいくしきい値の範囲が絵ごとに違った**
  （魚 0.50〜0.66 / イカ 0.55〜0.62 / タコ 0.40〜0.58）。1つの固定値ではどれかが必ず落ちる。
  かといって会場でつまみを触らせるのは核（アプリ操作0回）を壊すので、
  **写真ごとに何通りか試して、通る範囲の真ん中を選ぶ**ようにした（F-209）。
  下見は縮小画像で行うので 1 枚あたり 0.1 秒。
  種類の判定は「1本の走査線が絵を何回横切るか」で見る（F-210）。
  足のある生き物には**尾びれの動きを当てない**。足の1本を尾と取り違えて体がちぎれる。
  タコ・イカは横に切って左右へ波打たせ、速さも魚の半分にした（F-324）。
  実物3枚で、しきい値・向き・種類がすべて正しく通った。
- 2026-08-18 F-323: **絵の大きさを設定で変えられるようにした**（0.5〜2倍）。
  画面幅に対する割合（既定 7%）に倍率を掛ける形なので、
  画面の大きさに追従する性質（R-015）はそのまま残る。
  倍率を上げても**画面の短いほうの4割を超えない**ようにしてある。
  絵が画面より大きいと泳ぐ余地が無くなり、真ん中で止まってしまうため。
  実測（14匹）: 0.6倍 23.9fps / 1.0倍 23.8fps / 1.6倍 22.9fps。
  **大きさは速度にほとんど影響しない。**
- 2026-08-18 F-206〜F-208, F-321: **実物の絵1枚で見つけた2件を直し、尾びれが付け根から振れるようにした**。
  既定のしきい値で絵が消えて紙の裏写りだけが残っていた（R-018）、
  絵が縦向きに描かれていた（R-019）。どちらも会場で展示が成立しなくなる。
  そのうえで、取り込み時に体の芯と尾びれの位置を求めて保存し（F-208）、
  **尾びれだけを付け根で回す**ようにした（F-321）。胴の波より4分の1周期遅らせている。
  同じ位相だと体と尾が一枚板に見える。
  実測（実物50匹・各2回）: しなり無 24.4fps → 有 21.3fps（-13%）。
  尾びれの回転ぶんが 6 ポイント。重ければ「ひれの動き」を 0 にできる。
  向き・上下・尾びれの位置は **AI 無しで当たった**（確からしさ 0.95）が、**標本は1枚**。
  AI と比べるにはまだ足りない（`docs/設計-AI.md` §6）。
- 2026-08-17 F-320: **絵が魚のようにしなって泳ぐようにした**。
  絵を縦8本の帯に切り、**進む向きの後ろほど大きく**上下にずらす。
  背びれ尾びれを見分けているのではなく、「後ろほど大きく振れる」という
  泳ぎ方そのものを絵全体に当てている。**AI は使っていない**
  （子どもの絵に背びれがあるとは限らず、外すと絵が壊れて見えるため）。
  帯ごとに縦の傾きを掛けて隣とつなぐので、粗く切っても段差が出ない。
  実測（50匹）: 帯14本で -19%、**8本で -7%** だったので8本にした。
  重いときのために「ひれの動き」を 0 にできるスライダーを付けてある。
