# リハーサル手順

- 作成: 2026-08-14
- 対象: **Windows 実機**（会場で使うPC、または同等の1台）
- 所要: 通しで **60〜90分**。連続稼働の確認だけ別途3時間放置

## なぜやるか

いま未検証なのは次の6つで、**どれも会期を壊しうる**。
コードを足すより、この1回のほうが価値が高い。

| # | 未検証のこと | 起きうる最悪 |
|---|---|---|
| 1 | Windows で一度も起動していない | **そもそも起動しない** |
| 2 | 実物の絵で切り抜きを試していない | 絵が全部消える／紙が残る |
| 3 | 200枚/日・50匹同時の負荷 | 会期後半にカクつく・固まる |
| 4 | 8時間の連続稼働 | メモリが増え続けて落ちる |
| 5 | 異常系（フォルダ消失・容量不足・壊れた写真） | 復旧できない |
| 6 | 保存・フォルダ監視にテストが1件も無い | 取り込みが静かに壊れる |

**うまくいかなかった項目こそ持ち帰る価値がある。** 結果は下の記録欄に書く。

---

## 用意するもの

- Windows PC 1台（会場で使う予定のもの）
- **実際に子どもが描いた絵**（またはそれに近いもの）を **20枚以上**。
  クレヨン・色鉛筆・水性ペンなど、**画材がばらけているほどよい**
- **スキャナ**（会場で使う予定のもの）
- 大画面モニター（あれば。無ければPCの画面で代用）

---

## 0. 準備（10分）

exe を手に入れる。**GitHub から落とすのが早い**（PCに何も入れなくてよい）。

1. GitHub のリポジトリ → **Actions** タブ → **Windows ビルド**
2. 最新の緑チェックの実行を開き、下の **Artifacts** の
   `PaintingsAquarium-windows` を押して zip で落とす
3. 展開すると2つ入っている

| ファイル | 使いどころ |
|---|---|
| `PaintingsAquarium-Setup.exe` | 会場PCに入れて使う（今回はこちらで進める） |
| `PaintingsAquarium-portable.exe` | インストールできないPC用。USBから直接動く |

手元でビルドしたいときは、Node.js（20以上）を入れて `npm install` → `npm run dist:win`。
**Windows 上でビルドすること**（Linux からだと wine が要る。`docs/配布手順.md`）。

**合格**: exe が手に入る。
**だめなら**: エラーの全文を持ち帰る。ここで止まったら以降は進めない。

## 1. インストールと起動（10分）

1. exe を実行する
2. **「WindowsによってPCが保護されました」が出る**（想定どおり。未署名のため）
   → 「詳細情報」→「実行」
3. インストール先はそのまま。**管理者権限を求められないこと**を確認
4. 起動する

| 確認 | 合格の条件 |
|---|---|
| 起動 | 数秒で水色の画面が出る |
| 権限 | 管理者パスワードを聞かれない |
| 初回画面 | 「写真を入れるフォルダを決めてください」が出る |

**だめなら**: 画面をそのまま撮る。エラーが出るなら全文を控える。

---

## 2. 初回設定（5分）

1. 「フォルダを選ぶ」を押し、取り込み用のフォルダを作って選ぶ
   （例: `ドキュメント\お絵かき水族館\取り込み`）
2. `F` キーで全画面。`S` キーで設定が開くことを確認

**合格**: フォルダを選んだあと、画面が水槽に変わる。

---

## 2.5 スキャナの設定（10分）★ ここを外すと全部止まる

取り込みは**スキャナ**で行う（2026-08-18 決定）。
アプリ側の操作は0回のままにできるが、**スキャナ側の設定は最初に1回だけ要る**。

| 設定 | こうする | 外すとどうなる |
|---|---|---|
| **保存形式** | **JPEG**（または PNG） | **PDF は読めない**。既定が PDF のスキャナが多い。警告は出るが1枚も泳がない |
| **保存先** | アプリの取り込みフォルダ | ここが違うと、スタッフの操作が「毎回コピーする」に増える |
| **解像度** | **150〜300dpi** | 実測では 150 も 300 も取り込み **約2.9秒**（要件は5秒以内）。600dpi は要らない |
| **ファイル名** | **通し番号（リセットしない）** | 同じ名前＋同じ大きさは**二重取り込みとみなして黙って捨てる**。毎日 `img001` に戻る設定だと、絵が静かに消える |
| **地色除去（背景除去）** | **入**（あれば） | 紙の色が飛んで切り抜きが安定する |
| **原稿カバー** | **必ず閉じる** | 開けたままだと周囲が真っ黒に写り、**絵より大きい黒い塊**として泳ぐ |
| **紙の置き方** | **端に合わせてまっすぐ** | 大きく斜め（10度ほど）に置くと、台紙の見分けを外すことがある。プテラノドンが**飛ばずに歩く**（実測: 6度までは問題なし） |
| **自動傾き補正** | 入 | 照合（台紙の見分け）の余裕が増える |

**合格**: 紙を1枚スキャンすると、アプリを触らずに数秒で泳ぎ出す。
**記録すること**: 実際の設定値と、スキャンから泳ぎ出すまでの秒数。

> 開発側の実測（GPU無効の環境・A4）: 150dpi 2.9秒 / 300dpi 2.9秒。
> 切り抜きも種類の判定も正しく通った。**実機ではもっと速いはず**。

---

## 3. 切り抜きの調整（20分）★ ここが本番

**いちばん重要な工程。** しきい値は私の推定値のままなので、実物で合わせる。

1. 塗った紙を1枚スキャンする（保存先は取り込みフォルダ）
2. **数秒待つ**（アプリの操作は不要）

| 結果 | 意味 | どうするか |
|---|---|---|
| 絵だけが泳ぐ | 合格 | そのまま次へ |
| 何も出ない／警告が出る | 消えすぎ | `S` →「紙とみなす明るさ」を**上げる** |
| 白い四角ごと泳ぐ | 消えなさすぎ | 同じつまみを**下げる** |
| 絵のまわりに影の塊 | 原稿カバーが開いていた | カバーを閉じてスキャンし直す |

4. 合格するまで、つまみを動かして**別のファイル名で**入れ直す
   （同じ名前＋同じ大きさのファイルは二重に取り込まれない）
5. 決まったら、**画材の違う絵を5枚**入れて、同じ設定で全部通ることを確認

**記録すること**: 最終的な「明るさ」「色の薄さ」の数値。
**うまくいかない画材**があれば、その絵の写真を残す。

> ここで**どうしても合わない**場合、四隅に印を付けた台紙を印刷して使う案がある
>（`docs/要件定義.md` §4）。その判断のために、失敗した写真を必ず残すこと。

---

## 4. 通しの確認（10分）

絵を **20枚以上** 入れて、大画面（あれば）に全画面で映す。

| 確認 | 合格の条件 |
|---|---|
| 見つけやすさ | **自分の絵を10秒以内に見つけられる** |
| 重なり | 2枚が重なったまま並んで泳ぎ続けない（すれ違いはOK） |
| 登場 | 新しい絵が薄く小さく現れ、1〜2秒で普通の大きさになる |
| 背景 | 絵より背景に目が行かない |
| なめらかさ | カクつかない |

**背景が強すぎたら**: `S` →「背景の強さ」を下げる。0で無地になる。
**記録すること**: 背景の強さの最終値。

### なめらかさを数字で見る ★ 重点項目

**ここは必ず見てほしい。** 開発側の環境（GPU無効のソフトウェア描画）では
実機の数字が出せず、**唯一まったく分からない項目**がこれ。

開発用の起動（`npm run dev` で開いた画面）の URL に `?measure` を付けると、
画面の隅に fps が出る。インストールした版では出ない。

| fps | 判定 | やること |
|---|---|---|
| 50以上 | 合格 | そのまま |
| 30〜50 | 惜しい | `S` →「背景の強さ」を 0.6 くらいに下げて再測定 |
| 30未満 | 要対策 | 下の「重いときの手順」へ |

**重いときの手順**（上から順に試し、どこで直ったかを記録する）

1. `S` →「**同時に泳ぐ数**」を 50 → 30 → 20 と下げる
2. `S` →「**背景の強さ**」を 1.0 → 0.6 → 0.3 と下げる
3. それでも駄目なら、**どちらを下げても効かない**と記録して持ち帰る

> 開発側の実測では、**絵の枚数は fps にほぼ影響しなかった**
>（5匹 5.8fps / 50匹 5.7fps）。重いのは背景側で、
> 背景を切ると 56.5fps まで戻った（R-016）。
> つまり **1 より 2 のほうが効く可能性が高い**。ただしこれはソフトウェア描画での話で、
> GPU のある実機では傾向が変わりうる。**どちらが効いたかを必ず記録すること。**

## 5. 規模の確認（15分）

1. 絵を **50枚以上**（できれば100枚）取り込む。
   同じ写真をコピーしてファイル名を変えれば水増しできる
2. 全部泳いだ状態で 5分ほど眺める

| 確認 | 合格の条件 |
|---|---|
| 画面 | カクつかない。同時に泳ぐのは最新50匹まで |
| 取り込み速度 | 写真を入れてから泳ぎ出すまで**5秒以内** |
| 一覧 | `S` を押して**すぐ開く**（固まらない） |
| 同時に泳ぐ数 | `S` で 50 → 20 に変えると、画面の匹数がすぐ減る |
| 削除 | 一覧から1枚消すと、画面からも消える |

> 一覧は一度に60枚までしか出さない（R-014）。
> それ以上は「さらに60枚」を押す。**押しても固まらないこと**を確認する。

---

## 6. 異常系（10分）

わざと壊す。**会期中に必ず起きる**ので、ここで挙動を知っておく。

| やること | 合格の条件 |
|---|---|
| 取り込みフォルダを**アプリ起動中に削除**する | 落ちない。次に写真を入れても静かに無視される |
| フォルダを作り直して写真を入れる | `S` →「変更」で選び直せば再開する |
| **壊れたファイル**（テキストの拡張子を .jpg にしたもの）を入れる | 落ちない。読めない旨の警告が出る |
| **HEIC**（iPhoneの既定形式）を入れる | 「互換性優先にしてください」と出る |
| アプリを閉じて再起動 | **前の絵が全部残っている**。一斉にふわっと出たりしない |

**記録すること**: 落ちた場合は、そのときの操作。

---

## 7. 連続稼働（3時間・放置）

会期は8時間続く。**メモリが増え続けないか**だけ見る。

1. 50枚入れた状態で全画面にして放置
2. 3時間後、タスクマネージャーで **PaintingsAquarium のメモリ**を見る

**合格**: 開始直後と比べて**大きく増えていない**（目安: 2倍以内）。
**記録すること**: 開始時と3時間後のメモリ（MB）。
